# 15. Accessibility (ACC)

Part of the [search and AI visibility rules](overview.md). Priorities, owner tags and recorded decisions are in the overview.

The target is WCAG 2.2 AA. These rules are the website accessibility standard: content that is easy to see and read, full keyboard use, screen-reader support, interactions that do not depend on a mouse or on motion, forms and navigation that can be understood, and accessible media. The component contract is `guidelines/accessibility.html` (catalog card: Accessibility). Heading order is [REN-05](rendering.md). Image text alternatives are [IMG-04](images.md). AI browsing agents (ChatGPT, Gemini in Chrome, Claude in Chrome) read the same accessibility information screen readers use, so these rules also decide whether an agent can find a programme and book a consultation.

- **ACC-01 (P0) [Build]** Native HTML first. Navigation is `<a href>`, actions are `<button>`, and phone, WhatsApp and email use real `tel:`, `https://wa.me/` and `mailto:` links. Tiles that navigate are links. Add ARIA only when no native element does the job. **Check:** code review. No `<div>` or `<span>` with click handlers.
- **ACC-02 (P1) [Build]** Every page has `<header>`, `<nav>`, one `<main>` and `<footer>`. Each extra `<nav>` has a label (Main, Footer, Breadcrumb, Pagination). A "Skip to main content" link is the first focusable element. **Check:** press Tab once on any page and the skip link appears. An axe audit shows no landmark errors.
- **ACC-03 (P0) [Build]** Everything works by keyboard: the menu sheet, phone dropdown, language selector, accordions, gallery and the consultation form in every form it takes (page, modal, drawer). Focus is always visible (`--ring-focus`). Tab order follows the visual reading order. Focus is never trapped. A dialog is the only place focus is contained, and it can be left (ACC-05). **Check:** submit a test consultation from a condition page using only the keyboard. Tab from the skip link through the header, the page and the footer without a trap.
- **ACC-04 (P0) [Build]** The phone dropdown, language selector and menu button open on click or Enter, not only on hover, and expose `aria-expanded`. Essential information is never available only on hover. Site navigation never uses `role="menu"`. **Check:** open each with the keyboard. A screen reader announces expanded and collapsed. Anything a hover reveals is also available from the keyboard.
- **ACC-05 (P0) [Build]** The consultation modal or drawer and the mobile menu sheet are modal dialogs. They take focus on open, keep focus inside, close on Escape and return focus to the button that opened them. **Check:** open and close each with the keyboard.
- **ACC-06 (P0) [Build]** Every form field has a visible label associated with its input. Placeholder text is not a label. Buttons have a clear name. Errors appear as text next to the field, are linked with `aria-describedby`, and set `aria-invalid="true"`. The error says what is wrong and how to fix it. Errors never rely on colour alone. **Check:** submit an empty consultation form with a screen reader on. Each error is read, including how to fix it.
- **ACC-07 (P1) [Build]** The form result is announced in a live region: the success copy from [SKILL.md §6](../SKILL.md#section-6), or a failure message that offers phone and WhatsApp. **Check:** submit a test form with a screen reader on.
- **ACC-08 (P1) [Build]** Tables (tariff, `TimeTable`, `SpecTable`) use `<th scope>`. A screen reader reads each rate with its currency and unit. **Check:** screen reader review of the tariff page.
- **ACC-09 (P1) [Build]** Gallery thumbnails are labelled buttons ("View image 2 of 6") with the current one marked `aria-current="true"`. Nothing auto-rotates. **Check:** screen reader review of a gallery.
- **ACC-10 (P1) [Build]** Breadcrumbs and pagination sit in labelled `<nav>` elements, and the current item has `aria-current="page"`. **Check:** template review.
- **ACC-11 (P0) [Build]** Icon-only controls (phone, WhatsApp, menu, close, language) have an accessible name, and the icon is `aria-hidden="true"`. **Check:** an axe audit shows no empty buttons or links.
- **ACC-12 (P0) [Build]** Contrast meets the contract: 4.5:1 for body text and 3:1 for large text and control borders, with text on photography judged against the scrimmed photograph. Colour is never the only way meaning is shown. A link, status or error also uses text, an underline, an icon or a pattern. **Check:** an axe audit shows no contrast errors. A status that is only a colour change fails review.
- **ACC-13 (P1) [Build]** Targets are at least 24 × 24 pixels everywhere and 44 × 44 pixels on mobile. Body size and line spacing come from the type tokens. Do not set a smaller body size or a tighter line height. Pages work at 200% browser zoom and at 320 pixels wide without horizontal scrolling or lost content. **Check:** zoom to 200% and narrow the window to 320 pixels on each page type. Every sentence and control is still reachable.
- **ACC-14 (P1) [Build]** Animations and Astro View Transitions respect `prefers-reduced-motion`. Nothing flashes more than three times in one second. Do not animate something that does not help the person use the page. **Check:** turn on reduced motion in the OS. Movement stops and colour and opacity changes remain. No content flashes.
- **ACC-15 (P1) [Build]** axe-core runs inside the existing Playwright smoke tests on each page type, and any serious or critical issue fails CI. This adds `@axe-core/playwright` as a development dependency, so record it in [skill-stack.md](../skill-stack.md) under change control. **Check:** CI shows the accessibility results on every pull request.
- **ACC-16 (P1) [Ops]** Before launch and every quarter, run one full consultation journey with only a keyboard and one with a screen reader (NVDA on Windows or VoiceOver on Mac or iPhone). **Check:** a dated test note.
- **ACC-17 (P2) [Build]** Now and then, run Lighthouse's experimental "Agentic Browsing" audit on the homepage, a programme page and Book a Consultation. Fix accessibility and HTML findings. **Check:** a saved Lighthouse report.
- **ACC-18 (P1) [Build]** People have enough time. A page or a form does not expire. If a time limit is ever required, the person can turn it off, adjust it, or extend it before it ends. **Check:** leave the consultation form and the hosted-visits form open. Neither times out.
- **ACC-19 (P1) [Content]** Links and buttons say what they do. "Click here", "read more" and "learn more" are never the whole accessible name. Header and footer navigation are the same on every page. **Check:** a crawl of link text finds no generic names. The header and footer match on the home page, a programme page and a policy page.
- **ACC-20 (P1) [Build]** A CAPTCHA, if one is ever added, is not the only way to pass the check. It has an alternative that does not depend on vision, hearing or a mouse. Any sign-in is usable with a keyboard and a screen reader. **Check:** the consultation form has no CAPTCHA. A proposal to add one is reviewed against this rule before it is built.
- **ACC-21 (P1) [Build]** Video that contains speech has captions. Audio has a transcript. Meaningful visual information that the soundtrack does not already describe is described in text. The player is the native `<video>` element, so its controls are keyboard accessible. How the files are stored and marked up is [skill-video.md](../skill-video.md). **Check:** a speaking video has a default caption track and a transcript in the first HTML. Tab reaches play, pause and the caption control.
