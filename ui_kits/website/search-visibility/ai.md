# 18. AI answers, AI agents and local presence (AI)

Part of the [search and AI visibility rules](overview.md). Priorities, owner tags and recorded decisions are in the overview.

Google says there is no separate trick for AI answers: pages first need to be indexed and good in normal search. These rules make pages easier to quote and Shantara easier to recognise as one entity.

- **AI-01 (P1) [Content]** Guides and FAQ answers start with a direct one- or two-sentence answer. Each section under a question heading makes sense if quoted alone. **Check:** read each section out of context. It still answers its heading.
- **AI-02 (P1) [Content]** Headings are written as the plain questions guests ask, for example "Can I continue my medication during a stay?". **Check:** content review.
- **AI-03 (P1) [Content]** Pages give specific, checkable facts (programme durations, what is included, who the doctors are, distance from Calicut airport, meals) instead of general claims, using only verified facts. **Check:** content review against `content/` and the handbook.
- **AI-04 (P1) [Content]** Each guide covers its topic, including the follow-up questions a guest needs answered before deciding. AI search tools split one question into several related searches. The brief lists those questions before writing. Do not pad a guide to reach a question count. **Check:** each guide brief lists its related questions.
- **AI-05 (P0) [Ops]** Name, address, phone and email are identical everywhere Shantara controls: the website, Google Business Profile, every social profile and every directory listing. Use "Shantara Naturopathy Retreat", +91 9553 600 100 and heal@shantara.life. Those profiles are also the JSON-LD `sameAs` list. **Check:** a quarterly review of every listing.
- **AI-06 (P1) [Ops]** Shantara has its own claimed and verified Google Business Profile, linked only to Shantara. It is never merged with, or managed as part of, the Hygiene Nature Cure Hospital listing. Its category fits a medical clinic, its website link is `https://shantara.life/en`, and its photos are real. **Check:** Google Business Profile shows the profile as verified, with Shantara's name, phone, address and website link.
- **AI-07 (P1) [Build]** AI browsing agents can use the site: the ACC rules cover it. The consultation form also submits as a plain HTML form POST when JavaScript fails. **Check:** submit the form with JavaScript turned off. The submission arrives and the visitor sees a confirmation.
- **AI-08 (P2) [Build]** `/llms.txt` and `/llms-full.txt` are generated after the build from the Markdown twins (AI-13), never written by hand. `llms.txt` has the organisation's name as its H1 and its description as the blockquote, then one link per indexable page to the page's `.md` URL with the page's meta description, in footer order. `llms-full.txt` is every twin in one file. Both hold page text, links and descriptions only, nothing that reads as an instruction to a model. Google Search ignores `llms.txt` and no major AI search engine has confirmed using it. It is kept because it is cheap. **Check:** `npm run check:markdown` in the website repo.
- **AI-09 (P2) [Build]** Do not build AI booking integrations (Universal Commerce Protocol, WebMCP, agent checkout). Shantara takes consultations, not online bookings. **Check:** none needed.
- **AI-10 (P2) [Content]** Publish original first-party material others can cite: a sample daily schedule, menus, therapy explanations by Shantara's doctors, recordings of doctor talks. Any outcome statistic goes through [health claims](../copy/health-claims-and-compliance.md) first. **Check:** each piece is published and linked from the relevant pages.
- **AI-11 (P2) [Ops]** Build real mentions of Shantara on trusted sites: media coverage, doctor talks and events, the Hygiene Nature Cure Hospital history, and credible health and travel publications. No paid link schemes. This builds authority over time. It is not a formula for AI recommendations. **Check:** a quarterly review.
- **AI-12 (P1) [Build]** The `User-agent: *` group in robots.txt carries Cloudflare's `Content-Signal: search=yes, ai-input=yes, ai-train=yes`. `ai-train=yes` follows the recorded decision to allow training crawlers ([overview](overview.md#decisions)). Crawlers skip lines they do not recognise (RFC 9309), so validator warnings about the directive are ignored. **Check:** `npm run check:sitemap` compares robots.txt with `ROBOTS_TXT` in `src/lib/seo/crawling.mjs`.
- **AI-13 (P1) [Build]** Every page that site search indexes has a Markdown twin at its path plus `.md`, for example `/en/booking-terms.md`. The twin is converted from the built page's `<main>` after `astro build`. It leaves out what site search leaves out (breadcrumbs, table of contents, share bar, forms) and decoration, makes links absolute, and opens with front matter giving the canonical URL. There is no second content store, and no page is written for AI alone. noindex pages have no twin. **Check:** `npm run check:markdown` in the website repo.
- **AI-14 (P1) [Build]** Each representation names the other. The HTML head has `<link rel="alternate" type="text/markdown" href="<path>.md">`, and the HTML response has `Link: <<path>.md>; rel="alternate"; type="text/markdown"`. The Markdown response has `Content-Type: text/markdown; charset=utf-8` and `Link: <canonical>; rel="canonical", <path>; rel="alternate"; type="text/html"`. Both responses have `Vary: Accept`. **Check:** `npm run check:markdown`, then `curl -I` both URLs on the preview.
- **AI-15 (P1) [Infra]** A page URL serves HTML or its Markdown twin by the request's `Accept` header. A Netlify Edge Function makes the choice between build outputs and renders nothing. It compares q-values, so `text/html, text/markdown;q=0.5` gets HTML. A tie goes to Markdown only when the client names `text/markdown` itself, so a browser's `*/*` gets HTML. A request that accepts neither gets 406. A URL that names `.md` or `.txt` is served as asked. A page with no twin falls back to HTML when the client accepts it. The choice is never made by User-Agent: serving bots different content is cloaking. **Check:** `npm run check:markdown`. On the preview, `curl -H "Accept: text/markdown"` on a page returns Markdown with `Vary: Accept`, `Accept: text/html, text/markdown;q=0.5` returns HTML, and `Accept: image/png` returns 406. acceptmarkdown.com and isitagentready.com pass at launch.
- **AI-16 (P2) [Infra]** The same edge function logs every page, Markdown and `llms` request as one JSON line in the Edge Functions log: path, format served, status, raw User-Agent and Accept, referrer host and traffic class. It records no IP address and no cookie. Unknown clients are classified by exclusion: browsers, search and link-preview crawlers, scanners and bare HTTP clients are ruled out, and what is left is `other`, read together with the format it was served. Named AI clients are split by provider into training crawler, search index and on-demand fetcher, so a crawler is never counted as a reader. Search Console's and Bing's AI reports do not replace this log: they show neither coding agents nor on-demand fetchers. **Check:** a quarterly read of the log, including `.md` 404s, which show pages agents guess at.
