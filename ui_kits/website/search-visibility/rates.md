# 10. Rates (RATE)

Part of the [search and AI visibility rules](overview.md). Priorities, owner tags and recorded decisions are in the overview.

Rates appear only on the production tariff pages, one per currency at `/en/tariff/{code}`, and their printable client cards, read from the Keystatic Tariffs collection ([SKILL.md §1](../SKILL.md), [skill-ia.md](../skill-ia.md#tariff)). The one exception is the organisation's indicative `priceRange` in JSON-LD (RATE-01). This design system holds no rates, currencies or validity dates. The tariff has one entry per currency, in any number; each amount is entered exactly as Shantara's rate sheet gives it and is never converted, rounded or calculated.

- **RATE-01 (P0) [Build]** Rates appear only on the tariff pages (`/en/tariff/*`). Every other page links to `/en/tariff`, never to a currency page. The one exception is the organisation node's `priceRange` and `currenciesAccepted` in JSON-LD (SCHEMA-03), read from the tariff: an indicative range for the business, never an exact rate and never an `Offer`. **Check:** a build step searches `dist/` outside `/en/tariff/*` for every currency code in the tariff, every currency symbol before a digit, and any `Offer` node, and fails on a match. Bare figures are not matched, because small amounts collide with ordinary numbers (website D-72). It skips the organisation node's `priceRange` and `currenciesAccepted`, and the `llms.txt` lines that link to each currency's Markdown twin; `llms-full.txt` leaves the tariff pages out.
- **RATE-02 (P0) [Content]** Each rate states its currency (ISO code) and its unit (per room or per person, per night, and the occupancy), and the page states that rates include all taxes. Amounts appear exactly as entered. It is visible server-rendered text, never an image, tooltip or something that needs a click. A draft tariff is not published. **Check:** `curl` the tariff page. Every rate, currency and unit appears as text.
- **RATE-03 (P0) [Build]** The default currency is the Tariffs entry marked default. An entry may also be the default for listed countries (`defaultForCountries`). `/en/tariff` redirects (302, `Vary: Cookie`, never cached) to one currency's page: the visitor's own choice first (the `currency` cookie, set when they follow a currency link), then the entry that is the default for the request's country, then the default entry (website D-62, D-70). Each currency page shows the same figures to everyone; nothing on it changes with IP address, locale or device. Locale is not currency. **Check:** request `/en/tariff` with no cookie and no country (the default's page), with a listed country (that entry's page), and with the cookie set (the cookie's page).
- **RATE-04 (P1) [Build]** If a tariff page emits JSON-LD `Offer` nodes (one per room category and occupancy, in that page's currency), each `price` is a plain number that equals the visible figure, with an ISO `priceCurrency` and a `priceSpecification` with `valueAddedTaxIncluded: true`. No other page emits `Offer`. Visible figures carry a `data-rate` attribute so tests can read them. **Check:** an automated test compares each visible `data-rate` value with the JSON-LD price.
- **RATE-05 (P0) [Content]** Nothing Shantara's rate sheet marks internal reaches the site. Only the public all-inclusive rates, supplements, inclusions, exclusions, payment terms and cancellation policy are published. **Check:** before each tariff update, compare the tariff page with the public sections of the rate sheet. Nothing else appears.
